**一句话：** Day 7 之后的游戏，换成一个**由 Astra 从零写的新 App 外壳**，跑 v1 定下的 4 个核心模块（M1 Scène、M2 Jardin、M3 Répondeur、M4 Réplique）和 Carnet 数据层；内容全部写成数据文件；旧的单文件游戏冻结，只负责 Day 1–6，打完 Day 6 把存档交接给新外壳，从 Day 7 Martin 给水壶接着玩。

**四个变化：**
1. **复习自动打分**：5 种题型（听句选义 → 选词填空 → 词块排序 → 首字母打字 → 听写），按 FSRS 稳定度升级，答完一律播整句正确语音，错的稍后回来。不再有“记得/忘了”。

3. **两台 OpenAI 云电脑**：Astra（游戏开发）+ 新的视觉/动画电脑（候选 Sol 6.1，由 Pixel Studio 派任务）。
4. **团队重新分工**：Le CTO 只做系统维护和全局管理；我管内容策略、排期、验收；Neng 管法语和学习设计；Le Réalisateur 写剧情数据；Le Buzz 不变。

## 3. 产品：新外壳里玩什么

### 3.1 外壳形态
- **全屏 App 式，手机优先**（390×844 为基准，电脑上居中显示宽版）。去掉网站式标题栏、大段说明和页脚链接。
- **沿用 Astra 的视觉语言**：黄昏巴黎天台、奶油色纸卡、单一绿色主按钮、无衬线字体、低分辨率像素场景。
- **角色以游戏里现在的样子为准**（CHARACTER_BIBLE 的 A 层：小、无描边）【已核实：设定集写明 A 层是现行标准】。
- **首页“Aujourd’hui”**：一个场景画面 + 今天的 6 行（花园、正片、留言、群聊、跑腿、晚间重听）+ 真实分钟数。点一下就进下一件事。
- **导航只有 3 处**：Aujourd’hui、天台（花园 = 单词本）、设置。没有菜单栈。

### 3.2 四个模块（每个只有一个手势）
| 模块 | 一个手势 | v2 里的要点 |
|---|---|---|
| **M1 Scène** 场景听读 | 点一下下一句；长按慢速重听；点高亮词收进种子袋 | 理解检查用“指一指”（点画面里的东西），不弹选项菜单 |
| **M2 Jardin** 花园复习 | 点答案块（或打字） | 5 种自动打分题型，见 3.3；成长见 3.4 |
| **M3 Répondeur** 留言机 | 听 5–12 秒，填空，逐字母比对 | 只用玩家已经听懂的句子；Day 8 Noé 语音留言已定稿【已核实：DAY08_MODULE_MAP】 |
| **M4 Réplique** 回话 | 打字或按住说话，角色用反应纠错 | A1–A2 用受限答案 + 规则检查，$0；纠错三级：Hein ? → 提示 → recast |

### 3.3 M2 复习规则（已和你定过）
- **5 种题型**：R1 听原句选意思 → R2 选词填空 → R3 词块排序 → P1 首字母打字 → P2 听写（P2 先做降级版，有录好的音频后再正式上）。
- **升级**：新词 R1；稳定度 <3 天 R1/R2；3–14 天 R2/R3；>14 天 R3/P1（P2）。答错降一级；同一题型不连出 3 次。
- **打分**：错 = Again；对但慢（点选约 >8 秒、打字约 >15 秒、排序约 >18 秒）或错 1 个字母 = Hard；对 = Good。当天只有第一次作答进 FSRS。**秒数是设计假设，要实测再调**【假设】。
- **反馈**：答完一律播整句正确语音（**用我们已有的录制音频，不用浏览器 TTS**）；错题隔 3–5 张卡回来，直到答对一次。
- **干扰项**：同词性、同阴阳性、玩家见过的词，R1 不用同音词。另加一条：**至少一个干扰项和答案同一语义场**（比如都是厨房里的东西），解决“一眼排除”的问题【设计建议，需 Neng 确认】。
- **每天新词上限 10**，到期太多时自动减少（WORDLIST 已定 Carnet new-per-day = 10）【已核实】。

### 3.4 花园成长模型（隐藏照顾值 + 早上结算）

**原则：** 答题时只有浇水动画，植物不当场变。照顾的效果藏起来、攒起来，在某个早上一次性显现。玩家不知道浇多少会长，只知道“一直在照顾它”。

**公式草图（参数都是起点，要用模拟和你的试玩来调）【假设】：**

对每个花盆 p，在每个结算日 d：

- 掌握度 `M_p = 平均( min(1, ln(1+S_i) / ln(1+30)) )`，对盆里**已引入**的词 i 求平均；S_i 是 FSRS 稳定度（天）。稳定度 30 天以上算满分。
- 坚持度 `C_p = 过去 7 天里，这个盆有到期词且当天被复习完的天数 ÷ 有到期词的天数`（没有到期的日子不算缺勤）。
- 覆盖度 `V_p = 已引入词数 ÷ 盆里总词数`。
- 当日照顾值 `care_p = 0.6·M_p + 0.25·C_p + 0.15·V_p`（0–1）。
- 累计成长 `G_p += max(0, care_p − 0.3)`。照顾值低于 0.3 那天不增长，也**不倒扣**。

**阶段：** 种子 → 发芽 → 长叶 → 长高 → 花苞 → 开花（可再加“结果/分株”给后期）。进入阶段 k 需要同时满足 `G_p ≥ T_k` 和 `M_p ≥ m_k`。成长只升不降。
- 起点参数（按“每天认真玩”的玩家）：T = 1, 3, 6, 10, 15；m = 0, 0.15, 0.3, 0.45, 0.6。目标体感：第 2–3 天发芽，约 1 周长叶，2 周长高，3–4 周开花【假设，需模拟验证】。
- 每个盆的门槛加 ±10% 的固定随机偏移（按盆 ID 生成），让不同植物节奏不同，玩家摸不出规律。

**枯萎和休眠（永不死亡）：** 盆里超过一半的词已过期 ≥3 天 → 叶色变暗（Astra 原型已有“橄榄色休眠”画面）；≥14 天 → 休眠（叶子收起，但阶段保留）。复习完这个盆的到期词后，下一次早上结算恢复原样，并给一个“它醒了”的小画面。

**早上揭晓流程：**
1. 当天第一次打开游戏 → 按本地日期结算（距上次结算多天就逐天补算，最多补 7 天）。
2. 如果有盆升阶：首页先显示天台，镜头推到那个盆，播 2–3 秒的变化动画 + 一句角色台词（例如 Noé：« Regarde ! Elle a une nouvelle feuille ! »），再一行小字说是哪一组词（比如“厨房这组”）。点一下继续。
3. **节奏控制**：一个早上最多揭晓 1 个盆，其余顺延到第二天；同一个盆两次升阶至少间隔 2 天。这样惊喜是零散的、持续的。
4. 没有升阶就不打扰，直接进首页。
5. 结算是纯函数（输入：卡片状态 + 日期 + 历史），可单元测试，也可在“Atelier”调试面板里快进模拟。

### 3.5 单词本 = 花盆视图
点花盆就是单词本：这组词、阴阳性颜色标签（le·m 红 / la·f 蓝）、每个词的**剧情原句和出现过的场景**、掌握程度（用文字档位，如“刚认识 / 有点熟 / 很熟”，不显示 FSRS 术语）。点原句可以重听。不做红叉、不做分数。

### 3.6 每日循环
沿用 v1 §5：早上花园 15–25 分 → 正片 M1 20–25 分（内嵌 2–3 次 M4）→ 午后留言 M3 → 群聊 M4 → 跑腿 → 晚间重听。前期（Day 7–14）实际约 60–75 分钟，**随词库变大自然变长**，不靠硬凑。

## 4. 架构

### 4.1 仓库布局（建议：同一个仓库的 `app/` 文件夹）【待定】
```
appartement-411-src/
  index.html, js/...        旧游戏，冻结，只修 P0（Day 1–6）
  app/                      新外壳（Astra 唯一写入者）
    index.html  src/        外壳、路由、4 个模块、FSRS、成长结算
    tests/                  单元测试 + e2e（Playwright，390×844 与 1280×800）
    AGENTS.md               短的“不要做”规则
  content/                  内容数据（Réalisateur / Neng 维护）
    items/ lines/ days/ pots/
  assets/                   素材库（Pixel 管理，视觉电脑产出）
    manifest.json  sprites/ scenes/ plants/ fx/
```

理由：一个仓库、一套 Pages 部署、一套 CI，两边共用音频和词表；旧代码不在 `app/` 里，Astra 不会被它干扰。部署时旧游戏在根路径，新外壳在 `/app/`，Day 6 结束时跳转过去。

### 4.2 Carnet 数据层
沿用 v1：`Item`（词或词块，属于一个 pot）→ `Line`（一句带音频的法语，标注含哪些 Item、说话人、语域）→ `Encounter`（M1 遇见次数）→ `Card`（M2 的 FSRS 状态）→ `Evidence`（M2–M4 每次作答：对错、用时、题型）。另加 `PotState`（成长累计 G、阶段、最后结算日、待揭晓队列）。

### 4.3 内容即数据
- 一天 = 一个数据文件，是一串模块调用（v1 §7.2 的格式作为起点，最终格式由 Astra 提议、Neng 和 Réalisateur 确认）。
- 只允许 7 种步骤：`narr / line / point / choice / garden / dictee / reply`【已核实：v1 §6】。
- 编译器检查：未知 Item、缺音频、法语空格统一、答案泄露、tu/vous 语域、每天新项 ≤10、剧透词、素材是否存在于 manifest。**检查不过，内容进不了构建。**

### 4.4 存档交接（Day 6 → Day 7）
1. 旧游戏在 Day 6 结束时生成一个**交接存档**（JSON：版本号、玩家名、已遇见的词和次数、已有复习记录、Day 7 结局分支）。这是对冻结代码的**唯一一次小改动**，算 P0 级修改，需要你同意【待定，见 §10 第 2 题】。
2. 自动跳转到 `/app/`，新外壳读入；同一域名下可直接读 localStorage，另外提供“导出码 / 粘贴导入”作为后备。
3. 迁移规则：旧 FSRS 状态直接带过来；旧 `plantXp` 丢弃，成长从 0 开始（Day 7 才拿到水壶，本来就是起点）。
4. 测试：用合成存档（不用真实玩家存档）跑“旧 Day 6 → 新 Day 7”的 e2e。

### 4.5 测试与自动检查（G1）
每个 PR 必须：单元测试全过（FSRS、成长结算、打分、编译器）；e2e 黄金路径两种尺寸；0 控制台错误；截图 contact sheet；**按模拟节奏计算的真实分钟数**；以前的测试全部重跑（回归门，依据 mixed_model_editing 研究摘要）。
